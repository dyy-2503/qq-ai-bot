# 手机扫码与掉线自救

机房 IP 跑 QQ 机器人，**登录态会被周期性作废**（实测一天一次左右）。
症状是：机器人突然不说话，服务器上 `docker logs napcat` 里刷

```
[error] [Core] [Login] Login Error,ErrType: 1  ErrCode: 3
请扫描下面的二维码，然后在手Q上授权登录
```

`ErrCode 3` = 会话失效。不是崩溃，不用重启容器，**只需要重新扫码**。

---

## 为什么要在手机上能做

掉线经常发生在半夜或你不在电脑前的时候。电脑不常开，
所以"用 SSH 连回服务器拿二维码"这件事必须能在手机上完成。

## 一、服务器侧：`qr` 命令

装一个脚本 `/opt/qq-ai/bin/qr.sh`，再软链成 `qr`：

```bash
#!/usr/bin/env bash
# 默认只读当前二维码，不重启；--force 才重新生成
set -u
FORCE=0
[ "${1:-}" = "--force" ] && FORCE=1

conns=$(ss -tn 2>/dev/null | grep -c ':6199 ')
if [ "$conns" -gt 0 ] && [ "$FORCE" -eq 0 ]; then
  echo "QQ 当前在线（WS 连接数 $conns），不需要扫码。"
  exit 0
fi

[ "$FORCE" -eq 1 ] && { docker restart napcat >/dev/null 2>&1; sleep 20; }

url=$(docker logs --since 3m napcat 2>&1 | grep -a -o 'https://txz\.qq\.com/p?k=[^ ]*' | tail -1)
[ -z "$url" ] && { echo "近 3 分钟没有二维码，稍等或加 --force"; exit 1; }

echo "二维码链接（手机 QQ 里直接打开）："
echo "  $url"
command -v qrencode >/dev/null && qrencode -t ANSIUTF8 -m 1 "$url"
```

**默认不重启**是关键：重启容器会丢掉还活着的登录态，
把"只是没连上"变成"必须扫码"。

## 二、账号

不要用 root 密码登录。单独建一个账号，只给需要的权限：

```bash
useradd -m -s /bin/bash qqai
echo "qqai:<密码>" | chpasswd
usermod -aG sudo qqai
echo 'qqai ALL=(ALL) NOPASSWD:ALL' > /etc/sudoers.d/qqai
```

改 sshd：

```
PasswordAuthentication yes
PermitRootLogin prohibit-password
```

配 `fail2ban` 挡暴力破解。

## 三、手机端（Termius / JuiceSSH）

| 字段 | 值 |
|---|---|
| Host | `<SERVER_IP>` |
| Port | `22` |
| Username | `qqai` |
| Password | `<你设的密码>` |

连上后只需要记一个命令：

```bash
qr
```

- **在线** → 回"不需要扫码"
- **掉线** → 给出链接 + 终端二维码
- **强制重来** → `qr --force`

拿到链接后**直接在手机 QQ 里打开**，不用另一台设备扫。

## 四、看门狗要能区分两种"没连上"

| 情况 | 该怎么做 |
|---|---|
| 进程死了 / 容器停了 | 重启 |
| **最近 10 分钟日志里有 `Login Error`** | **什么都不做**，这是等扫码，重启也没用 |
| 真的断连（无报错） | 连续两次才重启 AstrBot，且 15 分钟内只重启一次 |

第一版看门狗只会"没连接就重启 AstrBot"，结果凌晨连着重启五次，
日志刷满，QQ 还是掉着——因为问题根本不在 AstrBot 那一侧。

```bash
login_err=$(docker logs --since 10m napcat 2>&1 | grep -a -c "Login Error")
if [ "$login_err" -gt 0 ]; then
  # 等扫码，不动任何东西
  exit 0
fi
```

## 五、一个走不通的路：给「我的电脑」发消息

试过让机器人定时给自己的号发一条消息，想让它出现在 QQ 的「我的电脑」会话里，
既当心跳又当保活。结果：

- `send_private_msg` 返回成功，日志也记了"已发送"
- **手机上「我的电脑」始终是空的**

原因：「我的电脑」是**设备之间的文件传输会话**，headless 的 Linux 客户端
没有对等的设备会话，消息发出去没有落点。

**结论**：心跳/报平安只能发到**你私聊**，或者干脆不发送、只探测登录态。
