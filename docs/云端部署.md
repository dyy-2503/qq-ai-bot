# 云端部署（Ubuntu 22.04 + Docker NapCat）

把整套东西从 Windows 搬到一台 Linux 云服务器，7×24 运行。
本文只写**能复现的步骤**和**踩过的坑**，路径按你自己的环境替换。

---

## 为什么搬

| 场景 | 本机 | 云端 |
|---|---|---|
| 宿舍/家里断电 | 每晚离线 | 不受影响 |
| QQ 掉线 | 少见 | **常见（机房 IP 风控）** |
| 成本 | 0 | 约 ¥90/月（2 核 2G） |

**核心矛盾**：云端更稳，但机房 IP 更容易被 QQ 判定风险。选云端就要接受"偶尔要重新扫码"。

## 前置

- 2 核 2G 起步（实测 AstrBot + NapCat 常驻约 820MB）
- Ubuntu 22.04（系统自带 Python 3.10，**AstrBot ≥4.14.7 要求 3.12**）
- 安全组只放行 22，**不要**放行 6185 / 6099 / 6199

## 一、Python 3.12

```bash
apt-get install -y software-properties-common
add-apt-repository -y ppa:deadsnakes/ppa
apt-get update && apt-get install -y python3.12 python3.12-venv
python3 -m venv /opt/qq-ai/venv   # 注意用 python3.12 建
/opt/qq-ai/venv/bin/pip install -i https://pypi.tuna.tsinghua.edu.cn/simple astrbot==<你的版本>
```

**坑**：直接 `pip install astrbot` 会装到 4.14.6（最后一个支持 3.10 的版本），
插件里用到的 `context.cron_manager`、`on_decorating_result` 等都会报错。
必须显式锁版本。

## 二、数据迁移

```bash
# 本机（Windows）
tar -czf data.tar.gz --exclude 'data/temp' --exclude 'data/webchat' data
scp data.tar.gz root@<SERVER>:/root/

# 服务器
cd /opt/qq-ai/astrbot && tar -xzf /root/data.tar.gz
```

`data/` 里包含：人格（`data_v4.db`）、九个插件、插件配置、B站库存、表情库。
**迁移前先停本地 AstrBot**，SQLite 在运行中复制可能拿到半截数据。

> 更稳的做法：用 `sqlite3` 的 `.backup` 或 Python 的 `conn.backup()` 导出快照，
> 见 `backup.sh`。

## 三、systemd

```ini
[Unit]
Description=AstrBot
After=network-online.target docker.service
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/qq-ai/astrbot
EnvironmentFile=/opt/qq-ai/.env
Environment=PYTHONIOENCODING=utf-8
ExecStart=/opt/qq-ai/venv/bin/astrbot run
Restart=always
RestartSec=5
StandardOutput=append:/opt/qq-ai/logs/astrbot.log
StandardError=append:/opt/qq-ai/logs/astrbot.log

[Install]
WantedBy=multi-user.target
```

`.env` 只放两个值（权限 600）：

```
DEEPSEEK_API_KEY=sk-<...>
NAPCAT_TOKEN=<...>
```

**坑**：AstrBot 必须在项目根目录下运行（`WorkingDirectory` 指向那层），
否则 `data/` 会建到别处，插件全部加载不到。

## 四、NapCat（Docker）

```bash
docker run -d --name napcat --restart=always --network host \
  -e NAPCAT_QQ=<BOT_QQ> \
  -v /opt/napcat:/app/napcat \
  mlikiowa/napcat-docker:latest
```

OneBot 反向 WS 配置写在 `/opt/napcat/config/onebot11_<BOT_QQ>.json`：

```json
{
  "network": {
    "websocketClients": [{
      "name": "astrbot",
      "enable": true,
      "url": "ws://127.0.0.1:6199/ws",
      "messagePostFormat": "array",
      "reportSelfMessage": false,
      "token": "",
      "debug": true,
      "heartInterval": 30000,
      "reconnectInterval": 3000
    }]
  }
}
```

### 三个必须知道的坑

1. **配置只在容器启动时读一次**。先写配置再 `docker restart`；
   反过来（先启动再改）改了等于没改，登录后也不会重新加载。
2. **`docker restart` 会丢登录态**。容器重启后大概率要重新扫码，
   所以看门狗**永远不要碰 napcat 容器**，只重启 AstrBot。
3. **反向 WS 的路径是 `/ws`**，且 AstrBot 端要求 OneBot 协议头
   （`X-Self-ID`、`X-Client-Role`）。用 Python 手工测连通性时漏了这两个头
   会得到 HTTP 400，看起来像"服务端坏了"。

## 五、验证

```bash
ss -tn | grep -c ':6199 '     # 2 = 双向连接建立
grep '适配器已连接' /opt/qq-ai/logs/astrbot.log | tail -1
```

`ss` 出现两条 ESTAB（一条来自 astrbot、一条来自 qq 进程）才算真的通。

## 七、数据源在机房的额外问题

**B 站 API 对数据中心 IP 返回 412**。同一份代码、同一个 Cookie，家庭宽带正常，
机房 IP 直接拒绝。修法：先取 `buvid3/buvid4` 指纹 cookie 带上，失败再退回
`bilibili-api` 库（它自己维护 buvid）。

```python
r = httpx.get("https://api.bilibili.com/x/frontend/finger/spi")
cookies = f"buvid3={b3}; buvid4={b4}; SESSDATA={sessdata}"
```
