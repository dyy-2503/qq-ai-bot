# QQ AI 好友机器人 · 部署手册

> 目标：在 QQ 私聊里，和一个"记得住事、说人话、有固定性格"的 AI 聊天，体验尽量接近真人好友。
> 技术栈：**NapCatQQ**（协议端）+ **AstrBot**（应用层）+ 任意大模型 API。
> 这份文档是给"改天在电脑版 DeepSeek Harness 里动手"时用的运行手册，照着往下走即可。

---

## 0. 三分钟看懂全貌

```
你的主号 ──私聊──┐
                 │
                 ▼
        ┌─────────────────┐
        │  QQ 小号（机器人）│  ← NapCat 用官方 NTQQ 客户端登录这个号
        └────────┬────────┘
                 │ OneBot v11 (WebSocket)
                 ▼
        ┌─────────────────┐
        │     AstrBot     │  ← 收消息、管记忆、调大模型、按人格回复
        └────────┬────────┘
                 │ HTTPS
                 ▼
        ┌─────────────────┐
        │ 大模型 API       │  DeepSeek / OpenAI 兼容 / 本地 Ollama
        └─────────────────┘
```

**职责边界，先记牢：**

| 组件 | 只干一件事 | 不负责 |
|---|---|---|
| NapCatQQ | 登录 QQ 小号，收发消息，对外暴露 OneBot v11 接口 | 不懂 AI，不管人格，不做记忆 |
| AstrBot | 接消息、拼上下文、调模型、拟人化发送、存记忆 | 不碰 QQ 协议，不解析登录态 |
| 大模型 API | 根据 prompt + 上下文生成回复 | 不管谁发的、发到哪 |

## 1. 开工前必须准备好的三样东西

### 1.1 一个 QQ 小号（不可省略）

**QQ 不允许一个账号给自己发消息**，所以必须是两个号：

- 你的主号 → 用来聊
- 机器人小号 → 用来挂 NapCat

⚠️ **绝对不要用主号挂机器人。** 一旦被风控，你同时失去主号和全部聊天记录。

小号开号建议：
- 注册后先正常用几天：加几个好友、发几条消息、看看空间，别注册完立刻挂机器人
- 关闭"设备锁"，或提前把验证方式准备好，否则远程登录会卡验证
- 手机号能收短信即可，不需要实名之外的额外资料

### 1.2 一台常开的机器（决定成败的关键）

NapCat 的本质是**注入官方 QQ NT 客户端进程**，所以它必须跑在：

- Windows（最省事）
- macOS
- x86 Linux（含 Docker 跑 Linux 版 QQ）

**你现在这台 Android 手机跑不了，Termux 里也没有可靠方案。**

按优先级选：

| 方案 | 成本 | 稳定性 | 备注 |
|---|---|---|---|
| 家里常年开的 Windows/Mac 电脑 | 0 | 中 | 要关掉自动休眠，断电/关机就掉线 |
| 旧笔记本装 Linux 长期跑 | 低 | 中高 | 推荐，最划算 |
| NAS / 软路由 Docker | 0 | 高 | 需 x86 架构，ARM 设备不推荐 |
| 云服务器（腾讯云/阿里云轻量） | 约 20–30 元/月 | **最高** | x86 / 2 核 2G 起，24h 在线，推荐 |

> 如果要 24 小时随叫随到，云服务器是最省心的答案。AMD 或 Intel 的轻量应用服务器就够，不需要 GPU。

### 1.3 一个大模型 API

| 选择 | 成本 | 适合 |
|---|---|---|
| DeepSeek | 极低（几块钱能聊很久） | **首选**，中文语感好，便宜 |
| 通义千问 / 智谱 GLM | 低 | 备选，都有 OpenAI 兼容接口 |
| OpenAI / Claude | 较高 | 预算充足、追求质量 |
| 本地 Ollama | 免费 | 有独立显卡（8G+ 显存）才考虑，否则慢到破坏聊天体验 |

## 2. 选型结论：为什么是 AstrBot 而不是 NoneBot2

| | AstrBot | NoneBot2 |
|---|---|---|
| 上手成本 | 有 WebUI，点几下填 API Key 就能聊 | 要写 Python、挑插件、配适配器 |
| 人格 / 上下文 | 内置人格功能和上下文管理 | 自己实现 |
| 长期记忆 | 插件生态现成（见第 7 节） | 需自己写或找插件 |
| 灵活度 | 够用，插件可扩展 | 极强，适合接业务系统 |
| **结论** | ✅ **你的场景选这个** | 只有要接业务逻辑时才选 |

如果后面发现 AstrBot 不够用，NapCat 那一层可以原封不动，只把上面换掉。

## 3. 方案 A：Docker 一键部署（推荐）

前提：机器上已装 Docker 与 Docker Compose。

### 3.1 建目录与 compose 文件

```bash
mkdir -p ~/qq-ai && cd ~/qq-ai
```

创建 `docker-compose.yml`：

```yaml
services:
  napcat:
    image: mlikiowa/napcat-docker:latest
    container_name: napcat
    restart: unless-stopped
    environment:
      - NAPCAT_UID=1000
      - NAPCAT_GID=1000
    ports:
      # 左边是宿主机端口，右边是容器内端口
      - "6099:6099"        # NapCat WebUI（登录/配置用）
      - "3000:3000"        # OneBot HTTP（可选）
      - "3001:3001"        # OneBot 正向 WS（可选）
    volumes:
      - ./napcat/config:/app/napcat/config
      - ./napcat/qq:/app/.config/QQ
    networks:
      - qqai

  astrbot:
    image: soulter/astrbot:latest
    container_name: astrbot
    restart: unless-stopped
    ports:
      - "6185:6185"        # AstrBot 后台 WebUI
    volumes:
      - ./astrbot/data:/AstrBot/data
    depends_on:
      - napcat
    networks:
      - qqai

networks:
  qqai:
    driver: bridge
```

> **端口说明**：`6099` / `6185` / `6199` 都是社区惯例默认值，**实际以首次启动后日志和各自 WebUI 里显示为准**。下面每一步都会告诉你怎么核对，不要硬背。

### 3.2 启动并登录 QQ 小号

```bash
docker compose up -d
docker compose logs -f napcat
```

日志里出现 WebUI 地址和**一次性 token**（形如 `http://<ip>:6099/webui?token=xxxx`），浏览器打开它：

1. 扫码登录 QQ 小号（推荐扫码，比密码稳定，也不容易触发异地风控）
2. 登录成功后，在 WebUI 里找到 **网络配置 / OneBot 配置**
3. 添加一个 **WebSocket 客户端（反向 WS）**：
   - URL 填 `ws://astrbot:6199/ws`
   - 开启并保存
   - 同时设置一个 **Access Token**（自己定一串随机字符，记下来，下一步要用）

> 容器名 `astrbot` 能直接当域名用，是因为两个容器在同一个 `qqai` 网络里。不要填 `127.0.0.1`——在容器里那是 NapCat 自己。

### 3.3 配置 AstrBot

浏览器打开 `http://<机器IP>:6185`

- 默认账号密码：`astrbot` / `astrbot`（**登录后第一件事就是改掉**）
- 进入「消息平台 / 适配器」，新增 **aiocqhttp（OneBot v11）**
  - 端口：`6199`（与上一步 NapCat 里填的一致）
  - Access Token：填刚才设置的那串
  - 保存并启用

### 3.4 验收

在 QQ 里用**主号**私聊小号发一句「在吗」。

- 小号没反应 → 看 `docker compose logs -f napcat` 有没有 WS 连接记录，再回看 3.2/3.3 的 URL 和 token 是否一致
- 有回复但很呆 → 正常，还没配人格，进入第 5 节

## 4. 方案 B：手动部署（不用 Docker）

适合 Windows 或想完全掌控版本的场景。

1. 安装**官方 QQ NT 客户端**并登录小号，保持运行
2. 安装 **LiteLoaderQQNT** 插件加载器（NapCat 以插件形式注入）
3. 从 NapCat 官方 Release 下载插件包，放进 LiteLoader 插件目录，重启 QQ
4. 此时 QQ 界面里会出现 NapCat 面板，配置 OneBot 反向 WS，URL 填 `ws://127.0.0.1:6199/ws`
5. AstrBot 按官方文档在 Python 3.10+ 环境安装：

```bash
git clone https://github.com/AstrBotDevs/AstrBot.git
cd AstrBot
pip install -r requirements.txt
python main.py
```

6. 其余配置与 3.3 完全一致

> 手动部署的优点：QQ 客户端是完整的，出问题好排查；缺点：QQ 每次大版本更新，NapCat 可能要跟着更新。

## 5. 让它"像好友"：六件事，缺一不可

框架只负责搬运消息。**体验好坏 90% 取决于这一节。** 建议按顺序做。

### 5.1 人格设定（最重要）

在 AstrBot 的「人格」里新建一个人格，写清这四层：

```text
【身份】你叫「小满」，是我认识多年的朋友，不是助手、不是客服。
【性格】温和但有点懒散，偶尔会吐槽我，不刻意讨好。说话简短，不用书面语。
【说话习惯】
- 每次回复 1~2 句，最多不超过 60 字，绝不写长篇。
- 不用列表、不用标题、不用加粗、不用 emoji 堆砌，最多一个表情。
- 不说"作为一个AI""希望对你有帮助""还有什么可以帮您"这类话。
- 偶尔只回"嗯""哈""行吧""真的假的"。
- 我说错话时会直接指出来，不捧场。
【关系】认识很久了，知道我在做开发，会关心我熬夜。
```

要点：
- **明确禁止"助手腔"**，这是最破坏沉浸感的
- **限制长度**，人聊天不会一段一段地发文
- **允许它不热情**，有脾气才像人
- 写得越具体越好，可以模仿某个真实朋友的说话方式

### 5.2 多轮上下文

在 AstrBot 的对话设置里开启会话上下文，窗口设 10–20 轮。太小会失忆，太大会拖慢响应、浪费 token。

### 5.3 长期记忆（必装插件）

没有这层，它过两天就会把你上周说过的事忘光，"好友感"会直接崩掉。

| 插件 | 作用 | 说明 |
|---|---|---|
| [astrbot_plugin_memory_beyond](https://github.com/AlanBacker/astrbot_plugin_memory_beyond) | 索引式档案存储 + 上下文压缩 | 不依赖 embedding 模型，配置简单，**先装这个** |
| [astrbot_plugin_self_learning](https://github.com/NickCharlie/astrbot_plugin_self_learning) | 学习说话风格、记录好感度、群组黑话 | 装了之后语气会越来越像你身边的人 |
| [astrbot_plugin_self_evolution](https://github.com/Renyus/astrbot_plugin_self_evolution) | 人格自演化 + 长期记忆 + 元编程 | 进阶，效果不确定，装前先读 README |

### 5.4 拟人化发送节奏

这一节最能拉开"AI 味"和"真人感"的差距。

- **按字数加随机延迟**：回复前 sleep `字数 × 0.15~0.4 秒`，不要秒回
- **长回复拆成多条**：超过 30 字就拆 2–3 条依次发，中间间隔 1–2 秒
- **禁止 Markdown**：在 prompt 里明确禁止，否则它会甩你一堆 `-` 和 `**`
- **偶尔发表情**：允许它在情绪明显时发一个表情包
- **允许沉默**：不是每条都必须回，可以在 prompt 里给它"不想回就不回"的许可

> AstrBot 各版本对"分段回复""延迟"的开关位置不同。如果当前版本没有对应选项，先装社区插件；实在没有再改代码——这部分逻辑很薄，几百行内能搞定。

### 5.5 私聊独占

⚠️ 这一条是安全项，务必配。

配置成**只对你的主号生效**，其他人私聊、群里 @ 它一律不理（或回一句固定话术）。

否则小号被陌生人加上之后，AI 会替你去应付别人，还可能把你的设定、记忆泄露出去。

### 5.6 主动消息（可选，加分项但别过火）

用 AstrBot 的定时任务：

- 早上 8:30 随机时间问个早安
- 深夜 23:30 之后如果没聊过，发一句"还没睡？"
- 每周挑一天分享一个随机话题

**频率要有节制**，一天 1–2 次即可。发太勤立刻露馅。

## 7. 验收清单

按顺序逐项打勾，任何一项不过都不用往下走：

- [ ] NapCat WebUI 里 QQ 小号显示在线
- [ ] NapCat 日志里能看到 `WebSocket` 连接成功记录
- [ ] AstrBot 适配器状态显示"已连接"
- [ ] 主号私聊小号能收到回复
- [ ] 回复符合人格（短、口语、无 Markdown）
- [ ] 连聊 5 轮，它记得第 1 轮说过的事
- [ ] 陌生人私聊它，它不理
- [ ] 重启机器后两个容器自动起来（`restart: unless-stopped` 生效）

## 8. 日常运维

| 场景 | 怎么做 |
|---|---|
| 开机自启 | Docker 已设 `restart: unless-stopped`；非 Docker 用 systemd 写服务 |
| 掉线重连 | NapCat 一般会自动重连；持续掉线看是否被要求验证，需在 WebUI 重新扫码 |
| 看日志 | `docker compose logs -f napcat` / `-f astrbot` |
| 更新 NapCat | `docker compose pull && docker compose up -d`，QQ 客户端大版本更新后必做 |
| 备份记忆 | 备份 `./astrbot/data`，这里存着人格和记忆 |
| 换模型 | AstrBot 后台换 provider 即可，不用动 NapCat |

## 9. 风险与边界（必读）

**合规与账号风险**
- 个人 QQ 没有官方机器人接口，NapCat 属于第三方注入方案，**违反 QQ 用户协议**，存在被风控甚至封号的概率
- 目前"单用户私聊 + 低频"是风控最低的用法；不要群发、不要高频、不要多群同时挂
- **只用小号**，出问题损失可控
- 企业/商用场景请走 [QQ 官方机器人平台](https://bot.q.qq.com/)，合规但只支持群和频道，做不了私聊陪伴

**能力边界**
- 做不了：语音/视频通话、朋友圈互动、转账红包、伪装"正在输入"状态
- 图片理解要模型支持视觉；语音需额外接 ASR/TTS，链路会长很多
- QQ 客户端更新后 NapCat 可能短暂失效，等作者适配

**预期落差**
- 它会偶尔冒出"AI 味"的句子，靠调 prompt 一点点磨
- 长期记忆是概率性的，不是数据库式精确召回
- 断线期间消息会丢，OneBot 这层不做离线补偿

## 10. 常见问题

| 现象 | 排查方向 |
|---|---|
| AstrBot 显示未连接 | NapCat 里填的 URL 是不是 `ws://astrbot:6199/ws`；token 两边是否完全一致；容器是否在同一 network |
| 小号在线但收不到消息 | 是否被 QQ 风控限制（WebUI 里看状态）；是否误开了私聊过滤 |
| 回复是长篇 Markdown | 人格 prompt 里禁止语没写死；上下文里残留了旧系统提示 |
| 回复很慢 | 模型 API 延迟；把上下文窗口调小；换更快模型 |
| 重启后要重新扫码 | 挂载目录没配对，登录态没持久化，回看 volumes 配置 |
| 被要求滑块/短信验证 | 异地登录触发，换用扫码登录，或在常用 IP 上操作 |
