## 3. 日常启停

**开机自启**：三个计划任务，登录时触发、无窗口

```powershell
schtasks /Query /TN "QQAI-NapCat"
schtasks /Query /TN "QQAI-AstrBot"
schtasks /Query /TN "QQAI-Watchdog"
schtasks /Delete /TN "QQAI-Watchdog" /F     # 不想要时
```

**手动启动**（各开一个窗口，关窗口即停；日志同样写进 logs\）：

```bat
<INSTALL_DIR>\start-napcat.bat
<INSTALL_DIR>\start-astrbot.bat
```

**只重启 AstrBot**（不需要重新扫码）：

```powershell
Get-Process python | Where-Object { $_.Path -like '<INSTALL_DIR>\venv\*' } | Stop-Process -Force
<INSTALL_DIR>\start-astrbot.bat
```

**只重启 NapCat**：

```powershell
Get-Process node | Where-Object { $_.Path -like '*\qq-ai\napcat\*' } | Stop-Process -Force
<INSTALL_DIR>\start-napcat.bat
```

> ⚠️ **千万别同时跑两个 NapCat 实例。** 同一个 QQ 号起两份会互相踢，日志也会穿插。
> 自检：`Get-Process node | Where-Object { $_.Path -like '*\qq-ai\napcat\*' }` 正常是 **2 个**（主进程 + worker）。

## 4. 日志

| 文件 | 内容 |
|---|---|
| `<INSTALL_DIR>\logs\napcat-out.log` | QQ 登录、收发消息、WS 连接、WebUI token、启动分隔行 |
| `<INSTALL_DIR>\logs\astrbot-out.log` | 收到什么、模型回了什么、报错、启动/退出码 |
| `<INSTALL_DIR>\logs\watchdog.log` | 掉线自动拉起记录（空 = 一直没掉过） |
| `<INSTALL_DIR>\astrbot\data\logs\` | AstrBot 自己的滚动日志 |

排障口诀：**先看 napcat 有没有"接收 <-"，再看 astrbot 有没有"Prepare to send"**。
前者没有 = QQ 侧没收到；后者没有 = 被白名单拦了或模型报错。

## 7. 改人格 / 改行为

**人格**存在 SQLite（`data_v4.db` 的 `personas` 表），不在配置里：

```powershell
<INSTALL_DIR>\venv\Scripts\python.exe <INSTALL_DIR>\tools\persona_append.py   # 追加一条规则
```

或 WebUI → 人格。改完重启 AstrBot。
当前人格：`小满`，约 415 字；核心约束是 1~2 句/60 字内、口语、禁 Markdown、允许不回、看到 `[图片]` 不猜。

**白名单**（只有主号能触发）在 `cmd_config.json`：

```json
"platform_settings": { "enable_id_white_list": true, "id_whitelist": ["qq:FriendMessage:<OWNER_QQ>"] }
```

格式是**会话 ID**，不是纯 QQ 号。加人写 `qq:FriendMessage:<QQ号>`。

**分段发送**：`platform_settings.segmented_reply`，现为阈值 40 字、间隔 1.5~3.5 秒。

## 8. 已知限制与坑

1. **启动脚本必须在 `<INSTALL_DIR>\astrbot` 目录下运行 astrbot**。
   这是 2026-10-20 重启后自启失败的根因：脚本 `cd` 到了 `<INSTALL_DIR>`，AstrBot 直接报
   `<INSTALL_DIR> is not a valid AstrBot root directory` 并退出。现在 `.bat` 已改为 `cd /d "%ROOT%astrbot"`。
   **教训：验证启动链要跑 `.bat`，不能只直接跑 exe。**
2. **AstrBot 重启不影响 QQ 登录**，NapCat 会在 5 秒内自动重连。
3. **重启 NapCat 后能快速登录**（`-q <BOT_QQ>` 生效）：实测重启电脑、杀进程重启都不需要重新扫码；
   只有 QQ 侧主动踢掉登录态时才要回 WebUI 重扫。
4. **DeepSeek 能看图，但要在 AstrBot 里声明**：模型的 `modalities` 必须是 `["text","image"]`，
   否则框架会在送模型前丢图，只留占位符——之前"只看到文件名"就是这个原因。
5. **主号在这台电脑上登过 QQ**，但 NapCat 用的是独立的一份 QQ（`<INSTALL_DIR>\napcat\...`），互不影响，不用退主号。
6. **QQ 风控**：小号 + 只私聊一个人 + 低频，是当前最安全的用法。被踢就重新扫码；频繁被踢考虑换号或上云服务器。
7. **GitHub 直连被墙**（github.com:443 超时），但 `api.github.com` 通。
   下 Release 用 `https://api.github.com/repos/<owner>/<repo>/releases/assets/<id>` + `Accept: application/octet-stream`。
8. **没做主动消息**：需要时在 AstrBot 加定时任务（早安/深夜问候），一天别超过 1~2 条。

## 补丁记录：记忆召回预算（2026-10-23）

改的是第三方插件 strbot_plugin_memory_beyond 的源码常量，**升级插件会覆盖，需要重新打**：

文件：strbot\data\plugins\astrbot_plugin_memory_beyond\core\recall.py

| 常量 | 原值 | 现值 | 含义 |
|---|---|---|---|
| FILE_CHARS | 3000 | 1200 | 单条记忆注入上限（字符） |
| TOTAL_CHARS | 9000 | 2500 | 每轮召回总预算（字符） |

配套配置（data\config\astrbot_plugin_memory_beyond_config.json）：
- 
ecall_max_files: 5 → **3**
- orget_after_days: 90 → **180**（enable_forgetting 仍为 false，暂未启用遗忘）

原文件备份：core\recall.py.bak-20261023

目的：降低每轮固定 token 开销，逼召回排序；避免 90 天悬崖一次性丢事。
若发现"开始忘事"，把这两个常量调回 3000/9000、
ecall_max_files 调回 5 即可。
